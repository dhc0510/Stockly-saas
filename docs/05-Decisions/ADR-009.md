# ADR-009 — Cantidades, reposición y reintegro en devoluciones de venta (STK-015)

Aprobado por el propietario el 2026-11-08.

- La devolución se inicia desde el comprobante original y selecciona artículos y cantidades de esa venta. Una venta admite varias devoluciones hasta agotar la cantidad vendida por línea. Cada devolución conserva su propio registro y la venta original permanece disponible para consulta.
- Registrar por línea la cantidad devuelta y la parte apta para vender. Solo la cantidad apta aumenta el saldo disponible en la sucursal de origen. La parte no apta queda registrada en la devolución.
- Ofrecer la acción «Reponer todo» después de revisar la mercadería y permitir ajustar por línea cuando haya unidades no aptas. Antes de confirmar, mostrar las cantidades devueltas y las que se repondrán.
- Ejemplo. De tres unidades devueltas, una está dañada. Se registran las tres devoluciones y se reponen dos unidades.

## Reintegro

- Calcular el importe de los artículos devueltos con el precio registrado en la venta original.
- En devoluciones sucesivas, calcular cada importe como la diferencia entre el acumulado redondeado de la línea y lo ya devuelto. Al devolver toda la línea, la suma coincide con su importe original.
- Si hubo un cobro registrado, sugerir sus medios de pago y permitir cambiar el medio o distribuir el importe según cómo se devolvió el dinero.
- Para ventas sin cobro registrado, guardar la devolución de mercadería sin registrar reintegro.


## Motivo

Cada devolución requiere un motivo. Las opciones son «Producto dañado», «Producto incorrecto», «El cliente cambió de opinión» y «Otro». Solo «Otro» requiere un detalle escrito. La cantidad apta para reposición se indica por separado.


## Comprobante electrónico

- Si Hacienda aceptó el comprobante original, generar una nota de crédito por los artículos y cantidades de cada devolución, vinculada al comprobante original.
- Si el original ya se envió y sigue en revisión, registrar la devolución y esperar la aceptación antes de emitir la nota.
- Si una devolución parcial llega antes de enviar el comprobante original, registrar la devolución y mantener el envío habitual del original. La nota de crédito queda pendiente hasta la aceptación.
- Si Hacienda rechaza el comprobante original, conservar la devolución, la reposición y el reintegro registrados. Mostrar «Revisión fiscal requerida» con el motivo del rechazo y no emitir una nota de crédito contra ese original.
- Usar la referencia por devolución de mercancía según el [anexo oficial v4.4](https://www.hacienda.go.cr/docs/ANEXOS_Y_ESTRUCTURAS_V4.4.pdf).


## Cierre después de una devolución parcial

- Mantener «Anular venta» para ventas sin devoluciones.
- Si ya hay una devolución, ofrecer «Devolver lo restante» para cerrar las cantidades pendientes. El saldo disponible, el reintegro y la nota de crédito se ajustan solo por lo que corresponda a esa devolución.


## Permisos

Confirmar devoluciones requiere el permiso «Registrar devoluciones» y acceso a la sucursal original. Este permiso es independiente del permiso para anular ventas completas.


## Consulta y folios

- Cada devolución tiene un folio consecutivo por empresa con formato DEV-0001.
- La venta original muestra los artículos devueltos, las cantidades pendientes, el reintegro y el estado de la nota de crédito cuando corresponda.
- El listado de Ventas identifica las ventas con devolución como «Devuelta parcialmente» o «Devuelta por completo».

## Confirmación y reintentos

- Volver a validar las cantidades pendientes al confirmar. Si dos cajas intentan devolver una cantidad que ya no alcanza para ambas operaciones, solo una confirma.
- Guardar en una sola transacción la devolución, la reposición de existencias y el reintegro registrado cuando corresponda.
- Si se pierde la respuesta de confirmación, un reintento de la misma operación recupera el folio guardado sin repetir sus efectos.

Cada devolución con reposición genera un movimiento vinculado a su folio DEV. El movimiento registra solo las cantidades aptas en la ubicación original y se consulta en Historial.

## Correcciones

La devolución se puede editar hasta confirmar. Una vez confirmada, queda fija en el historial. Una operación separada y vinculada para corregir devoluciones confirmadas queda para una funcionalidad posterior.
