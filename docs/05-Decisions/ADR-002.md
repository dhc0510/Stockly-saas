# ADR-002 — Aislamiento multiempresa con MySQL

Estado: aprobado mediante PLAN STK-004 el 2026-11-05. No implementado.

## Contexto y decisión

Stockly usa Java/Spring Boot y MySQL. Se aprueba monolito modular y base compartida: companies y users; cuentas de negocio vinculadas a una empresa, identidad SaaS diferenciada. Datos operativos llevan companyId y relaciones compatibles con esa empresa. Los servicios/repositorios obtienen el ámbito de identidad autenticada y filtran explícitamente; las rutas globales de gestión requieren administrador SaaS.

La autorización en servidor, restricciones e integración con STK-005 son obligatorias. Probar aislamiento con identidades de dos empresas e intentos por ID. No habilitar rutas públicas para eludir la dependencia de autenticación.

## Consecuencias

Operación compartida y migraciones comunes; exige disciplina en todas las consultas y pruebas de aislamiento. No se utiliza RLS de PostgreSQL. ADR-001 sigue siendo un borrador anterior no aprobado, incompatible con el stack vigente. Cambiar esta estrategia requiere aprobación y actualización del PLAN.
